# 人脸考勤系统功能修改与验收说明

本次修改完成了学生签到、教师发起签到、请假详情、考勤统计、Excel 导出和小组签到流程的统一。默认本地 H2 数据库会在启动时自动升级；MySQL 环境须先执行 `database/migration-20260905-attendance.sql`。

## 已实现功能

- 签到完成后的业务提示统一为“签到成功”或“签到成功（迟到）”。人脸识别只作为认证过程，认证凭据两分钟内有效且只能消费一次。
- 活体检测改为双眼“睁开—闭合—重新睁开”的连续动作检测，并核验每帧身份一致性。小组签到不能关闭活体检测。
- 学生个人签到可选择快速检测或活体检测：快速检测直接核验身份；活体检测先眨眼、再左右转头，并适当延长动作采集窗口。首页进入当前签到会自动带入课程。
- 管理员只负责学生、教师和课程信息；教师负责发起签到、维护本人课程学生、修正特殊考勤、审批请假及查看统计；学生资料只读且不提供人脸注册入口。
- 签到页适配电脑、平板和手机。手机端摄像头、课程选择、主要按钮和状态提示在常用竖屏尺寸内完整显示。
- 教师可发起 5、10、15 分钟或 1–240 分钟的自定义签到，可选择迟到阈值。截止时间由服务端保存，刷新页面不会重置。
- 签到开始时保存本次应签到名单；结束后自动将未签到且未批准请假的学生结算为缺勤，将批准请假的学生结算为请假。
- 小组组长须勾选本次实际签到成员并确认名单，每名成员分别完成人脸和眨眼核验，只处理勾选人员。
- 请假详情展示课程、学生、开始和结束时间、时长、原因、申请时间、状态、审批教师、审批时间和审批意见。
- 统计页支持课程、班级、学生和日期筛选，展示数据卡片、状态饼图、学生出勤率柱状图、按日/周/月趋势折线图及明细表。
- 明细支持按姓名、学号、正常、迟到、请假、缺勤和出勤率排序，并可按异常条件筛选。
- 导出文件为真正的 `.xlsx` 工作簿，包含日期、课程、班级、姓名、学号、签到时间、考勤状态和请假信息；导出条件与页面筛选一致。
- 教师可在课程详情中维护学生班级。考勤状态调整和请假审批写入审计记录。

## 状态与统计口径

考勤状态为 `PRESENT`（正常）、`LATE`（迟到）、`LEAVE`（请假）和 `ABSENT`（缺勤）。任务尚未结束且没有记录时为页面层的“未签到”，不会提前写入缺勤。

出勤率公式：

`（正常次数 + 迟到次数）÷（正常次数 + 迟到次数 + 缺勤次数）× 100%`

已批准请假不进入分母。有效应考勤次数为零时显示“—”。统计、首页汇总、图表和导出都只使用已结束的考勤任务。

## 关键接口

- `POST /attendance/sessions/{courseId}`：教师发起限时签到。
- `GET /attendance/sessions/{courseId}`：获取服务端签到状态和截止时间。
- `GET /attendance/report/{courseId}`：按条件获取统计数据。
- `GET /attendance/export-xlsx`：按条件导出 Excel。
- `PUT /attendance/student-class/{courseId}/{studentId}`：教师设置学生班级。
- `GET /attendance/summary`：获取当前角色首页汇总。

## 升级与运行

1. MySQL 环境执行 `database/migration-20260905-attendance.sql`；默认 H2 模式无需手动操作。
2. 在 `face-recognition` 中重新执行 `pip install -r requirements.txt`。项目已包含 `models/face_landmarker.task`。
3. 重启人脸识别服务和 Java 后端，再重新构建前端或 Android 包。

## 说明

眨眼动作检测可降低静态照片代签风险，但不等同于专用防回放模型。正式环境如需抵御高质量视频回放，应接入具备攻击类型评测报告的防伪模型或硬件深度摄像头。
